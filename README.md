# Всем ЁУ!
Сталкивались ли вы с необходимостью модерировать ваш чат в телеграмме от спама или оскорблений? Модераторы **не всегда** могут быть в сети, да и от **наплыва ботов** модераторы могут не справляться. *Это не их вина, просто мы все люди.* Есть специальные боты они могут работать очень даже хорошо - но вот незадача за них надо платить или в вашей группе будет фигурировать реклама от этого же бота. А если вам **мало** встроенных функций бота? Или вы переживаете, что бот **собирает данные о пользователях в группе?**

**Есть решение!** У многих из вас наверняка завалялся старый **android смартфон** и благодаря нему вполне успешно можно *заселфхостить* своего бота! Но наверняка не каждому захочется писать своего бота с нуля. **А это и не обязательно!**

**ChatProtect** - это **open-source** бот на **python** для ==автоматической== модерации чата в телеграмме с *тонкой настройкой*, а по мимо этого бот также имеет систему *"шуток"*.Но обо всё по порядку - вот оглавление если интересует, что то конкретное вы знаете, что делать:

[Обработка сообщений](#text-handler)
## Минимальные требования
 - **Android** смартфон - по поводу версии android ничего не скажу, мой бот работает на **11**, а сейчас для демонстрации буду запускать на **10** версии android
 - **Termux *(не из Google Play**, так как там устаревшая версия)*, **Я рекомендую поставить F-Droid**

> [!WARNING]
> Кстати о **F-Droid, Я не могу не упомянуть Google хочет запретить ставить приложения не из Google Play**, не думаю, что стоит говорить, что это одно из **главных преимуществ android.** Поэтому если **Вы** за **свободный android** - можете перейти по ссылке в описании и **подписать петицию.**
## Установка
Переходим на https://f-droid.org/ и нажимаем **"СКАЧАТЬ F-DROID"**, перекидываем **.apk-шник** на **android** мобилу и устанавливаем. Заходим ждём обновления репозиториев и вписываем в поиске **Termux** и скачиваем *(Termux эмулятор)*, во время установки вас запросит дать доступ на **установку приложений - разрешаем**.
Переходим в **Termux**, выполняем 
```bash
pkg update
```
 чтобы **обновить** репозитории, а затем
 ```bash
pkg upgrade
 ```
для установки обновлений. На все вопросы просто нажимайте **Enter**. 
Затем если вы **соображаете** можете установить **git** и выполнить git clone и установить зависимости через
```bash
pip install -r requirements.txt
```

Но для тех кто не шарит, переходим на репозиторий на [Github](https://github.com/AnonimNEO/ChatProtect) или [Codeberg](https://codeberg.org/AnonimNEO/ChatProtect). Нажимаем **скачать .Zip архив**. Распаковываем его в нужный вам каталог.

## Команды
Здесь будут отображаться команды и их аргументы, команды которые доступны только модераторам будут отмечаться таким значком. 
- **/help** - вывод справки по командам (данные находятся в ключе **help_text** в файле локализации).
- **/status** - статус работы бота если команда была вызвана модератором в приватном чате то будет выведена дополнительная информация.
- **/about** - Информация о боте (данные находятся в ключе **about_bot_text** в файле локализации)
- **/rules** - правила группы (данные находятся в ключе **bot_rules** в файле локализации).
- **/reputation_constants** - Константы расчёта репутации.
- **/report** - Обратная свзязь для отчётов об ошибках, отчёты сохраняются в **REPORT_DIR/user_id/дата_и_время_отчёта.txt**.
- **/data** - Вывод данных о пользователе, количество нарушений, репутация и т.п.
- Уточню, что система определения пользователя работает так, если вы ответили на **чьё то сообщение** то целью бота станет то на **чьё сообщение** вы отвечаете, затем **аргумент в команде** это или *user_id* или *@user_name* ***==(но лучше user_id)==***, а если нет ни того не другого то **вы**, *но касается это не всех команд*, чтобы вы не нароком не заблокировали себя.
- **/rep** - повысить репутацию пользователя, если вы модератор то будет добавлена репутация от модераторов.
- **/minus_rep** - понизить репутацию. Также если вы модератор то вы можете указать количество изменяемой репутации.
- **/mute, /unmute - для мута и размута пользователя.
- **/ban**, /unban - блокировка и разблокировка пользователя.
- /**clear** - снятие нарушений с пользователя.
- **/cache_media** - кеширует все медиа файлы в MEDIA_DIR и его подкаталогах (подробней в разделе система шуток)

## Обработка сообщений
<a name="text-handler"></a>
При появлении нового сообщения бот получает весь текст сообщения, и происходит несколько проверок:

Первое сообщение ссылка? - бан (настраивается).

0) **Этап** - проверка напрямую, найдено запрещённое слово? - добавляем **1 нарушение**.
1) **Этап** - убираем все символы (кроме алфавита и цифр), найдено запрещённое слово? - добавляем **2 нарушения**.
2) **Этап** - убираем не все символы, а затем замена символов *(Правила замены символов находятся в **DATA_DIR/replacements.txt**)*, найдено запрещённое слово? - добавляем **3 нарушения**.

Если сообщение было изменено то происходит повторная проверка в теже **3 этапа**, найдено нарушение? - удаляем сообщение, добавляем **в 2 раза больше нарушения** *(в зависимости от этапа).*

> [!NOTE]
> Список запрещённых слов при нахождении которых бот будет **удалять** сообщения, находятся в **DATA_DIR/bad_words.txt**, каждое слово на новой строке.

> [!Note]
> Для всех этапов можно включить проверку на нечёткое совпадение через **difflib** *(опечатки)*

Так же по умолчанию если пользователь отправил больше 13 сообщений за минуту то получит **SPAM_VIOLATION_MODIFICATOR** **нарушений** или **бан** (настраивается).

> [!Note]
> Есть система исключений, в **DATA_DIR/exception.txt** сожержатся слова ислючения *(например оскорблять)*. Система исключений работает так: если слов исключений **больше** или **столько же сколько и слов нарушений** то сообщение считается **валидным**.

ID модераторов находятся в **DATA_DIR/moderators.txt**.
## Система бэкапов
На случай если, что-то пойдёт не так реализована автоматическая система бэкапов. Весь каталог **DATA_DIR** архивируется *(настраивается)* и сохраняется в **BACKUPS_DIR**.
## Система шуток
В DATA_DIR есть trigger.json в котором содержится данные для конкретных слов (тригеров), на которые бот реагирует соответственно.

Бот может удалить сообщений, ответить на него текстом и отправить медиа файл (всё это можно комбинировать и настраивается отдельно в triggers.json).

Так как отправка медиа может быть крайне затратной по ресурсам - поэтому в боте реализована система "кеширования". Когда медиа файл был успешно отправлен в чат в базу данных записывается имя файла и id сообщения, в следующий раз при отправке того же медиа бот перешлёт старое сообщение (в случае ошибки отправит медиа заново). Для автоматического кеширования в личке с ботом напишите команду /cache_media - для кеширования не кешированых медиа и /cache_media all - для удаления старых id из базы и кеширования всех медиа заново.

Если система шуток включена то бот после проверки сообщения (если оно не было удалено за нарушение), проверит на совпадение по TRIGGERS_FILE. структура TRIGGERS_FILE:

```json
{
  "replies": [
    {
      "keywords": ["че делать", "чё делать"],
      "response": "Снимать штаны и бегать",
      "media": null,
      "delete_message": false
    },
    {
      "keywords": ["ты бот", "бот ты"],
      "response": "Сам ты бот.",
      "media": "media/ты_бот/",
      "delete_message": false
    }
  ]
}
```

- keywords - список слов на которые будет реагировать бот.
- response - текстовый ответ (null - чтобы было без ответа).
- media - путь к медиа файлу (если указан каталог будет выбран случайный медиа файл в нём).
- delete_message - удалить ли сообщение.

> [!Note]
> В config.py можно увеличить задержку между кеширование медиа файлов.
